khojki-ocr architecture

How a scanned Khojki page becomes checked Unicode text, how the model behind it was trained, and how the result was measured. Click any box for what it does, why it works that way and where it falls short.

Added after the take-home submission, not part of the v1.0 submission. Every number on this page is written by tools/make_arch_page.py from files in results/. No scans or line images are included.

Training

Text, then images, then a model

Run

Turn on Data flow to follow test line p18_l02 through the run side and see what each stage hands to the next.

  1. page PNG → segment.py: the page image, one grayscale array.
  2. segment.py → recognize.py: line boxes in page pixels, 16 of them on page_18. Each box is cropped from the page.
  3. recognize.py → normalize.py: raw text for one crop: 𑈃𑈟𑈬𑈴𑈺𑈠𑈭𑈦𑈩𑈙𑈬𑈺𑈙𑈡𑈺𑈡𑈬𑈙𑈬𑈴𑈺𑈡𑈮𑈙𑈮𑈺૪ U+11203 U+1121F U+1122C U+11234 U+1123A U+11220 …
  4. normalize.py → validate.py: normalized text plus a repair count (0 repairs here): 𑈃𑈟𑈬𑈴𑈺𑈠𑈭𑈦𑈩𑈙𑈬𑈺𑈙𑈡𑈺𑈡𑈬𑈙𑈬𑈴𑈺𑈡𑈮𑈙𑈮𑈺૪ U+11203 U+1121F U+1122C U+11234 U+1123A U+11220 …
  5. validate.py → score.py: the error list for the line: an empty list (no rule broken).
  6. score.py → results/out/: a render score for the line: 0.769.
  7. results/out/: one JSON record per line, written with the page's txt file and overlay: {"text": "𑈃𑈟𑈬𑈴𑈺𑈠𑈭𑈦𑈩𑈙𑈬𑈺𑈙𑈡𑈺𑈡𑈬𑈙𑈬𑈴𑈺𑈡𑈮𑈙𑈮𑈺૪", "repairs": {}, "errors": [], "render_score": 0.769}
